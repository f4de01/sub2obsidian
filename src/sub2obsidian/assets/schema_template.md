# Schema

> 本文件由 sub2obsidian 的 Schema 模板（版本 $schema_version）在初始化时生成，此后归本知识库所有，可随 Wiki 演进自行修改；工具不会再覆盖它。`CLAUDE.md` 与 `AGENTS.md` 内容相同，改一份时请同步另一份。

本知识库是一个 Karpathy 式 LLM Wiki：`sub2obsidian` 工具把用户在抖音、B站、公众号收藏的**来源**采集为**原始材料**；你（agent）按本 Schema 把原始材料**编译**成按**概念**组织、互相链接的 **Wiki**。用户只读 Wiki、在 Wiki 里写**批注**，并在「我的笔记」里写自己的思考。

用户在本目录对你说「编译」时，执行下文「编译流程」。问询、存档为综述页、全库体检、筛选建议的流程将在后续版本的 Schema 中补全；在那之前用户要求这些操作时，按本 Schema 的页面规范与不可违反的规则尽力完成，并在 `log.md` 记一笔。

## 不可违反的规则

1. **原始材料只读**：不得修改、移动或删除 `$raw_dir/` 中的任何文件。来源状态只能通过 `sub2obsidian` 命令变更。
2. **我的笔记只读**：不得改动 `$notes_dir/` 中的任何文件；编译时把它作为**优先级最高的来源**读入（见「我的笔记」）。
3. **批注原样保留**：用户的批注（`> [!我]` callout）一个字都不能改、不能删，改写页面时随它所批注的内容一起移动（见「批注」）。你自己永远不写 `[!我]` callout。
4. **每条论断都有出处**：概念页中的每条论断都要带出处，指向对应的来源页；视频来源带时间戳（见「出处」）。没有出处的内容不得写进概念页。
5. **每次编译以一次 git 提交结束**，提交说明列出编译的来源与新建/改写的概念页。

## 知识库结构

| 位置 | 内容 | 谁来写 |
| --- | --- | --- |
| `$raw_dir/` | 原始材料：每个来源一个目录 | 只由 `sub2obsidian` 写入，只增不改 |
| `$sources_dir/` | 来源页：单个来源的摘要，作为概念页论断的证据 | agent |
| `$concepts_dir/` | 概念页：Wiki 的主产物，围绕一个知识概念汇总多个来源 | agent（用户只写批注） |
| `$domains_dir/` | 主题域入口页（如 AI、理财） | agent |
| `$syntheses_dir/` | 综述页：用户要求存档的问询答案（规范见后续版本） | agent |
| `$notes_dir/` | 我的笔记：用户亲手写的思考 | 只有用户 |
| `$attachments_dir/` | 用户粘贴的附件 | 用户 |
| `index.md` | Wiki 页面索引 | agent |
| `log.md` | 操作日志，只追加 | agent |
| `$status_page` | Dataview 来源状态页 | `sub2obsidian` 初始化时写入，不要改 |

Wiki 内部一律用 wikilink：`[[页面名]]`、`[[页面名#小节]]`、`[[页面名|显示文字]]`；指向平台原文用 Markdown 链接。页面名就是文件名（不含 `.md`），全库唯一。

## 原始材料

每个来源一个目录 `$raw_dir/<平台>/<平台内ID>/`，平台为 `bilibili`（B站）、`douyin`（抖音）、`wechat`（公众号）；页面与提交说明中一律写括号里的平台中文名：

- `元数据.md`：frontmatter 字段为 平台、平台内ID、规范链接、类型（视频/文章/图文）、标题、作者（UP主、公众号名等发布者）、署名（文章原文署名的作者，可空）、发布时间、时长（秒）、采集途径、采集时间、来源状态、筛选建议、失败原因；正文为标题、封面与简介。
- `口播稿.md`（视频）：frontmatter 的「口播稿来源」注明来自平台字幕还是 ASR 转写；正文每段一行，以该段起始时刻 `[时:分:秒]` 开头。口播稿未经纠错，同音错字（如把「RAG」听成「rag」「瑞格」）按上下文理解，写进 Wiki 时用正确写法。
- `正文.md`（文章、图文）：标题下一行注明出处（公众号文章为公众号名、原文署名作者、发布时间与原文链接），之后是原文转成的 Markdown，图片以 `![](图01.png)` 引用同一目录中的图片文件；`封面.jpg` 等图片。

**来源状态**：待筛、已拒绝、已通过、已采集、已转写、已编译、已失效。**可编译** = 文章或图文「已采集」，或视频「已转写」。编译完成后由 `sub2obsidian mark-compiled` 转为「已编译」。

## 页面规范

### 来源页

一个来源一篇，放在 `$sources_dir/`。

- **页面名**：来源标题，去掉 `\ / : * ? " < > | # ^ [ ]` 等不能用于文件名或 wikilink 的字符，以及「【干货】」「建议收藏」之类与内容无关的修饰；超过 40 字时截短。与已有页面重名时在末尾加「（<平台中文名> <平台内ID>）」。
- **frontmatter**：

```yaml
---
页面类型: 来源页
平台: bilibili
平台内ID: BV1GJ411x7h7
规范链接: https://www.bilibili.com/video/BV1GJ411x7h7
来源类型: 视频            # 视频 / 文章 / 图文
作者: 某知识区UP主
发布时间: 2024-05-01      # 只写日期；元数据缺失时留空
时长: "10:12"            # 视频才有
原始材料: "[[$raw_dir/bilibili/BV1GJ411x7h7/元数据|原始材料]]"
主题域:
  - "[[AI]]"
概念:                    # 引用了本来源的概念页（含作为同内容版本被引用）
  - "[[RAG]]"
同内容版本: []            # 见「同内容版本」
编译时间: 2026-01-01
---
```

- **正文**结构：

```markdown
# <来源标题（原样）>

> [!info] B站 · 某知识区UP主 · 2024-05-01 · 10:12 · [原视频](https://www.bilibili.com/video/BV1GJ411x7h7)

## 摘要
三到五句话：这个来源讲了什么、结论是什么、适合谁看。

## 要点
- 按原始材料的顺序列出知识要点，视频每条带时间戳出处（B站 写跳转链接，抖音写时间戳文本）。
- 文章、图文：按原文的小节用三级标题分组（`### 小节名`），概念页即可用 `[[来源页#小节名]]` 精确引用；图中的知识按「读图规则」转写在对应小节里。

## 涉及的概念
- [[RAG]]：本来源对该概念贡献了什么（一句话）。

## 评价
可信度、时效性、局限、立场（如带货、营销号）、与其他来源的关系。没有可说的就省略本节。
```

### 概念页

Wiki 的主产物，放在 `$concepts_dir/`。

- **粒度**：一个**能独立讲清楚的概念**——能写出一段不依赖其他页面就成立的定义，且用户会单独查找它。只作为另一个概念的步骤或细节出现的内容，写进那个概念页的小节；某个小节被三个以上其他页面引用、或长到喧宾夺主时，再拆成独立概念页。工具、产品、方法论、指标都可以是概念；人物、公司一般不单独成页，除非来源围绕它讲了可复用的知识。
- **页面名（标题）**：用业界通用叫法——中文社区通用英文缩写的就用缩写（`RAG`、`MCP`），通用中文的就用中文（`提示词工程`）。其他叫法（中文全称、英文全称、常见别称、常见误写）全部写进 `aliases`，让任何一种叫法都能链到同一页。新建前先查 `index.md` 和全部概念页的 `aliases`，已有同义页面时并入，不得新建重复概念。
- **frontmatter**：

```yaml
---
页面类型: 概念页
aliases:
  - 检索增强生成
  - Retrieval-Augmented Generation
主题域:
  - "[[AI]]"
证据数: 2                # 独立证据的数量：同内容版本只算一份，我的笔记不计
创建时间: 2026-01-01
更新时间: 2026-01-01
---
```

- **正文**结构（小节顺序固定；没有内容的小节写「暂无」，「分歧」小节没有分歧时写「暂无分歧」）：

```markdown
# RAG

一句话定义（index.md 的摘要即取自这里）。

## 定义
用两三段话讲清楚它是什么、解决什么问题、核心机制。每条论断带出处。

## 要点
- 关键事实、原理、适用条件、常见误区。每条带出处。

## 实操与示例
- 怎么做、具体步骤、参数、命令、例子。每条带出处。

## 关系
- 上位：大语言模型应用
- 组成 / 依赖：[[向量数据库]]、Embedding
- 对比：微调——一句话说明区别
- 相关：长上下文

## 分歧
暂无分歧

## 出处
- [[来源页B]]（公众号 · 作者 · 2025-03-01）
- [[来源页A]]（B站 · 作者 · 2024-05-01）；同内容版本：[[来源页C]]（抖音）
- [[我的笔记/RAG 实践心得]]（我的笔记）
```

- **关系**：类型用 上位、下位、组成 / 依赖、被依赖、对比、相关；对比写一句区别。关系本身是论断时（如「X 是 Y 的基础设施」）同样带出处。已有概念页的概念写成 wikilink；还没有概念页的概念写纯文本、不加链接，等它有了页面再改成链接（不要为了消灭纯文本去造只有一句话的空页面）。
- **出处小节**：列出本页引用过的全部来源页，按发布时间倒序；同一组同内容版本写在一行；我的笔记列在最后。
- **合并而不是追加**：新来源并入已有概念页时，把新知识揉进对应小节、与已有论断合并去重（合并后的论断保留所有出处），不要在页尾追加「来源 X 说……」段落。已有论断只有在被等价论断吸收时才可删去，且其出处要转移过去；与新说法冲突的旧论断不删，移入「分歧」。

### 主题域入口页

Wiki 的顶层划分，放在 `$domains_dir/<主题域>.md`。优先归入已有主题域；只有新概念明显不属于任何已有主题域时才新建，并在 `log.md` 中注明。

```markdown
---
页面类型: 主题域
aliases: []
---
# AI

一段话说明本主题域覆盖什么。

## 概念
按子主题分组列出本主题域的全部概念页，每个后面跟一句话定义。
- 检索与知识库：[[RAG]]——……；[[向量数据库]]——……

## 待裁决的分歧
- [[RAG#分歧]]：一句话描述争议点
```

## 出处

概念页中每条论断后紧跟出处，放在全角括号里；多个出处用「；」分隔：

| 来源 | 出处写法 |
| --- | --- |
| B站 视频 | `（[[来源页]] [03:25](https://www.bilibili.com/video/BV1GJ411x7h7?t=205)）`：规范链接后加 `?t=秒数`，点击即跳到原视频该秒 |
| 抖音 视频 | `（[[来源页]] 03:25）`：抖音不支持时间戳跳转，只写时间戳文本 |
| 文章、图文 | `（[[来源页]]）`，能定位到来源页小节时写 `（[[来源页#小节]]）` |
| 我的笔记 | `（[[我的笔记/文件名]]）` |

- **时间戳**取口播稿中说出该论断的那一行开头的 `[时:分:秒]`：秒数 = 时×3600 + 分×60 + 秒；显示为 `分:秒`（满一小时为 `时:分:秒`）。例：`[00:03:25]` → `[03:25](…?t=205)`；`[01:02:05]` → `[1:02:05](…?t=3725)`。时间戳不得超出视频时长。
- 论断由多段口播支撑时，引用最能代表它的那一处；不要编造原始材料里没有的时间戳。
- 来源页「要点」中的条目同样带时间戳（此时可省略 `[[来源页]]` 本身）。

## 分歧

不同来源对同一问题说法冲突时（事实、数字、推荐做法相互矛盾，或说法随时间过时），不要自行裁决、不要悄悄覆盖旧说法，在概念页「分歧」小节并列保留各方说法：

```markdown
## 分歧

### 长上下文模型出现后，RAG 是否还有必要？
- **2025-03-01** 有必要，长上下文成本高、召回不稳定（[[来源页B]] [05:10](…?t=310)）
- **2024-05-01** 长上下文会取代 RAG（[[来源页A]] [02:00](…?t=120)）
- 状态：待裁决
```

- 每个争议点一个三级标题，写成一个问题；每种说法一行，以该来源的**发布时间**（元数据中的发布时间，取日期；缺失时用采集时间并注明）开头，**新说法在前**。
- 正文（定义、要点）中涉及争议的地方不选边，写明「说法不一，见 [[#分歧]]」。
- 我的笔记或批注表达了用户的判断时，把它作为一行写进分歧（以「我的笔记：」或「批注：」开头），状态改为「已裁决：……（依据我的笔记 / 批注）」，正文按用户的判断写；各方说法仍保留。这一行的日期：我的笔记取它最后一次提交的日期（`git log -1 --format=%cs -- <文件>`，未提交时取当天），批注取你第一次读到它的编译日期。
- 只是侧重点不同、可以同时成立的说法不算分歧，合并进正文即可。
- 新增或已裁决的分歧在主题域入口页的「待裁决的分歧」中同步。

## 批注

用户在概念页（及其他 Wiki 页面）里用 callout 写随手意见：

```markdown
> [!我] 实测 chunk 设成 500 字效果更好
> 第二行也属于这条批注
```

- 批注从 `> [!我]` 开始，到连续的 `>` 行结束；整块逐字保留，包括空格与换行。
- 批注紧跟在它所批注的段落或列表项之后。改写页面时，被批注的内容移到哪里，批注就跟到哪里；被批注的内容合并进别处时，批注跟到合并后的位置；实在无法判断时留在原小节末尾。任何情况下都不删除批注。
- 批注表达的意见优先级与我的笔记相同：批注指出某条论断有误或补充了经验时，相应调整正文（以批注为出处时写 `（批注）`），但批注本身不动。

## 我的笔记

- `$notes_dir/` 中的笔记是用户亲手写的思考与实践经验，是**优先级最高的来源**：与来源说法冲突时，正文以笔记为准，来源的说法记入「分歧」。
- 只读不写；不要求有固定格式。引用写 `（[[我的笔记/文件名]]）`。
- 每次编译都要读：与本批涉及概念相关的笔记（在 `$notes_dir/` 中搜索概念标题与 aliases），以及自上次编译以来新增或改动的笔记（`git log --since` 上次编译日期，或 `git status $notes_dir`）。

## 同内容版本

同一份内容在不同平台或以不同形式发布（跨平台搬运、文章版与视频版、同一作者的重发）对应多个来源，即**同内容版本**。

- **识别**：作者相同或注明转载，且标题相近、口播稿或正文高度重合。写来源页前先在 `index.md` 和 `$sources_dir/` 中查找同作者、相近标题的来源。
- **关联**：每个版本仍各写一篇来源页；在彼此 frontmatter 的 `同内容版本` 中互相列出（如 `同内容版本: ["[[来源页C]]"]`），并在「评价」中注明。
- **只算一份证据**：概念页引用时选一个代表版本（优先 B站 等可跳转时间戳的版本，其次发布最早的），其余写在同一出处后：`（[[来源页A]] [03:25](…?t=205)；同内容版本：[[来源页C]]）`。「出处」小节中同一组版本写在一行，`证据数` 只算一次。不同版本绝不能被当作「多方印证」。

## 读图规则

- 原始材料中的图片（文章配图、图文帖的图、带字的封面）要逐张看。图中的知识——幻灯片要点、表格、代码截图、流程与架构——**写成文字**：表格写成 Markdown 表格，代码写成代码块，流程写成有序列表，并带出处（`（[[来源页]] 图 3）`）。
- 只嵌入**关键示意图**：文字难以替代的架构图、流程图、对比图，每个概念页一般不超过两张。直接嵌入原始材料中的文件，不复制：`![[$raw_dir/wechat/<平台内ID>/图片名.png|600]]`，下一行写图注与出处。
- 装饰图、表情包、广告、二维码、普通封面不嵌入也不转述。

## index.md

全部 Wiki 页面的索引，每次编译（以及任何新增、删除、重命名页面的操作）都要更新。用户与你都先读它来定位页面。格式：

```markdown
# 索引

## 主题域
- [[AI]] —— 一句话说明（概念 12 · 来源 30）

## 概念
### AI
- [[RAG]]（检索增强生成）—— 一句话定义

## 来源
- [[来源页]] —— B站 · 作者 · 2024-05-01

## 综述
```

- 「概念」按主题域分三级标题，同一主题域内按页面名排序；括号里写最常用的一个别名。一个概念属于多个主题域时只列在第一个下。
- 「来源」按发布时间倒序。

## log.md

操作日志，**只在末尾追加**，从不改写旧记录。每条一个二级标题：`## [YYYY-MM-DD] <操作> | <摘要>`，操作为 init、编译、问询、体检、Schema 之一（`grep "^## \[" log.md | tail -5` 即可看最近五条）。编译记录：

```markdown
## [2026-01-01] 编译 | 3 个来源

- 来源：[[来源页A]]、[[来源页B]]、[[来源页C]]
- 新建概念页：[[RAG]]、[[向量数据库]]
- 改写概念页：[[大语言模型]]
- 新增分歧：[[RAG#分歧]]（长上下文模型出现后，RAG 是否还有必要？——待裁决）
- 同内容版本：[[来源页A]] ↔ [[来源页C]]
- 读入我的笔记：[[我的笔记/RAG 实践心得]]
- 一并提交：用户在 [[RAG]] 中新写的批注
- 体检：修复断链 1 处；遗留：Embedding 尚无概念页
```

没有内容的条目（如没有新建概念页）写「无」；新建了主题域时加一行「新增主题域」。

## 编译流程

用户说「编译」时，按顺序执行。所有 `sub2obsidian` 命令都在本知识库目录中执行并带上 `--vault .`。

1. **取可编译的来源**：执行 `sub2obsidian status --vault .`，读「可编译的来源」列表（每行开头的 `<平台>/<平台内ID>` 即来源目录 `$raw_dir/<平台>/<平台内ID>/`）。没有可编译的来源就告诉用户并结束。用户指定了范围就只编译那些；超过 10 个时分批，每批走完整流程、各自提交。同时执行 `git status --short`：Wiki 中未提交的改动多半是用户新写的批注，照常保留，随本次编译一起提交。
2. **写来源页**：逐个读来源目录中的 `元数据.md`、`口播稿.md` 或 `正文.md`、图片（按「读图规则」），先识别同内容版本，再按「来源页」规范写来源页。
3. **并入或新建概念页**：读 `index.md`、相关的已有概念页及我的笔记，确定本批来源涉及的概念；按「概念页」规范并入已有页面或新建页面，补全「关系」，处理「分歧」与「同内容版本」，更新 `证据数` 与 `更新时间`，并更新主题域入口页。
4. **更新 index 和 log**：按上文格式更新 `index.md`，在 `log.md` 末尾追加一条编译记录。
5. **轻量体检**：对本次新建或改写的页面逐项检查并修好：
   - 每条论断都有出处；出处中的来源页存在；时间戳与口播稿对得上、不超出时长，B站 链接的 `?t=` 秒数与显示的时间一致；
   - wikilink 都能解析到已有页面或别名，`[[页面#小节]]` 的小节确实存在（没有页面的概念写纯文本，见「关系」）；
   - 标题与 aliases 不与其他页面重复；没有新造出与已有概念同义的页面；
   - 分歧按日期新说法在前；同内容版本只算一份证据；
   - 用 `git diff` 核对：原有的每个 `> [!我]` 批注块都原样还在；`$raw_dir/` 与 `$notes_dir/` 中没有任何文件被你改动。
6. **标记已编译**：执行 `sub2obsidian mark-compiled --vault . <平台>/<平台内ID> …`，列出本批全部来源。命令拒绝时（来源不可编译或写错），一个来源都不会被改动：按提示修正后重新执行，成功之前不要提交。
7. **git 提交**：只提交 Wiki、索引、日志与本批来源的元数据：

   ```
   git add -- Wiki index.md log.md $raw_dir/<平台>/<平台内ID>/元数据.md …
   git commit -F <提交说明文件>
   ```

   提交说明先写到系统临时目录中的文件（不要写进知识库），再用 `-F` 提交。格式（来源一行一个，写成「平台中文名 平台内ID 标题」，标题照抄元数据；概念页写页面名）：

   ```
   编译: 3 个来源

   来源:
   - B站 BV1GJ411x7h7 【大模型】RAG 到底是什么？10 分钟讲清楚
   - 公众号 AbCdEf123 RAG 已死？长上下文时代的检索
   新建概念页:
   - RAG
   - 向量数据库
   改写概念页:
   - 大语言模型
   ```

   提交后向用户简要汇报：编译了哪些来源，新建和改写了哪些概念页，新增了哪些待裁决的分歧。
