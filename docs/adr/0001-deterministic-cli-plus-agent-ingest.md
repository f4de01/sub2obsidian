# 采集与转写用确定性 CLI，编译交给 agent 会话

采集、筛选元数据、转写、初始化知识库这些步骤由本仓库的 Python CLI 确定性地完成，产出只增不改的原始材料；而「原始材料 → Wiki」的编译不写代码，由用户在知识库目录中开启 agent 会话（如 Claude Code），按知识库里的 Schema 增量执行。原因是编译的核心价值在于跨页面判断——把新来源并入已有概念页、识别同一内容的不同版本、记录分歧——这类判断写成固定的 API 流水线难以控制质量，而 agent 读 Schema 后能做，且可由用户攒批触发、在场把关；每次编译以一次 git 提交落盘，可审阅、可回退。

## Considered Options

- **全自动流水线（脚本直接调 LLM API 生成并改写页面）**：无人值守，但跨页面合并质量不可控、改坏难察觉，且有持续 API 费用。被否决。
- **仅生成每来源一篇摘要（不维护概念页）**：易自动化，但不是 LLM Wiki，知识不会沉淀到概念层面。被否决。

## Consequences

- 编译需要用户主动发起，Wiki 的更新节奏取决于用户攒批的频率。
- 编译行为的「代码」就是 Schema；改进编译质量 = 修改知识库中的 Schema（及本仓库的 Schema 模板），而不是改 CLI。
